# gdtools

[English](README.md) · **Русский**

Инструмент для Geometry Dash 2.2: правка сейва (`CCGameManager.dat`) и живой памяти
запущенного процесса. Консоль + визуальный интерфейс.

Собран под Windows и .NET Framework 4.8, компилируется тем же `csc.exe`, что лежит в
системе — **ничего ставить не нужно**, ни Python, ни рантаймов, ни Geode.

```
gd_currency.exe   консоль: разбор сейва, правка сейва, работа с памятью
gd_gui.exe        визуальный интерфейс (двойной клик)
gd_tool.exe       меню в консоли для тех, кому лень помнить команды
```

## Возможности

- **Разбор сейва.** `CCGameManager.dat` = `XOR 0x0B ( base64url( gzip( plist ) ) )`.
  Парсер и сериализатор побайтово совместимы с оригиналом (проверяется `verify`).
- **Правка сейва.** С записью через временный файл, обратным чтением и сверкой —
  оригинал подменяется только после успешной проверки. Автоматически бэкапит.
- **Правка живой памяти.** Статистика в 2.2 лежит не в plist-строках, а в хеш-таблице
  `GameStatsManager`. Значение на экране = `current − delta`, поэтому пишем
  `current = цель + delta`.
- **`bulk`** — вся валюта за один проход по памяти (полный скан ~900 МБ занимает
  20-40 секунд, поэтому сканируем один раз, а не по стату).
- **`wallet`** — показывает то, что реально на экране, а не то, что в файле.
- **GUI** — тёмная и светлая темы, группы «Валюта»/«Аккаунт», поиск, отметка строк
  протяжкой мыши, панель выбранного.

## Сборка

Из корня репозитория:

```cmd
build.cmd
```

Скрипт найдёт `csc.exe` в `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319`,
соберёт все три exe и положит их рядом. Если `gd_gui.exe` в этот момент запущен,
скрипт переименует его в `gd_gui_old.exe` и продолжит — Windows разрешает
переименование работающего файла.

Требуется только .NET Framework 4.8 (в Windows 10/11 он есть из коробки).

## Использование

### Консоль

```
  SAVE:
    gd_currency info                                   разбор сейва
    gd_currency stats                                  ID статов + расшифровка
    gd_currency ls [путь] [-max N]                     плоский список значений
    gd_currency get <путь>                             одно значение, напр. GS_value/14
    gd_currency set <путь> <значение>                  накрутить (игра должна быть ЗАКРЫТА)
    gd_currency setrun <стат> <значение>               ЗАКРЫТЬ игру -> накрутить -> запустить заново
    gd_currency find <число|строка> [-path префикс]    поиск по значению
    gd_currency verify                                 round-trip, побайтовая сверка
    gd_currency dump [-o файл.xml]                     выгрузить plist в xml
    gd_currency snapshot [-o b.json]                   снимок всех значений
    gd_currency diff <снимок.json>                     что изменилось в игре

  MEM (живой процесс, как в Cheat Engine):
    gd_currency live <стат> <значение>        ПРАВИТ СТАТ В ЗАПУЩЕННОЙ ИГРЕ (в т.ч. орбы)
    gd_currency bulk <стат>=<число> [...]     НАКРУТИТЬ ВСЮ ВАЛЮТУ ЗА ОДИН ПРОХОД
    gd_currency wallet [-csv]                 вся живая статистика: что реально на экране
    gd_currency nodedump <стат>               сырой дамп узла таблицы (отладка)
    gd_currency statmap                       plist-записи статистики в памяти
    gd_currency live-scan <стат> <значение> [-current N] [-watch N]
        старый метод: поиск по значению (когда live не справился)
    gd_currency live-narrow <новое число>
        сузить кандидатов после того, как значение изменилось в игре
    gd_currency live-probe -seconds N [-min N] [-want <число>] [-maxchanges N]
        НЕ знает числа: следит за всей памятью и ловит ячейки, которые меняются,
        группирует их по значению. ИГРАЙ, пока идёт наблюдение.
    gd_currency live-write <адреса> <значение>
        записать значение по конкретным адресам
    gd_currency mem-scan   <число> [-type int32|int64|float|double] [-writable] [-align N]
    gd_currency mem-scan   -bytes <hex>  (? вместо байта)   AOB-скан
    gd_currency mem-narrow <число>                     сузить после изменения в игре
    gd_currency mem-write  <число> [-seconds N]        записать / держать (freeze)
    gd_currency mem-dump   <адрес> [длина]             hex-дамп памяти

  Общее:
    -f файл       путь к .dat (по умолчанию %LOCALAPPDATA%\GeometryDash\CCGameManager.dat)
    -proc имя/PID процесс-цель для mem-*, по умолчанию GeometryDash
```

Примеры:

```cmd
gd_currency wallet -csv
gd_currency bulk orbs=500000 diamonds=999 usercoins=999 stars=1000
gd_currency setrun stars 1000
```

### Интерфейс

`gd_gui.exe` — запускается манифестом `requireAdministrator`, потому что иначе
`WriteProcessMemory` в чужой процесс не пройдёт.

- рельса слева переключает группы: **Валюта** / **Аккаунт** / сброс / смена темы;
- строку можно отметить кликом по галочке, протяжкой по галочкам (диапазон
  тянется от первой отмеченной, строки вне диапазона возвращаются как были),
  или кнопками «Отметить всё» / «Снять всё»;
- клик по названию — обычное выделение (Ctrl / Shift работают), кнопка
  «накрутить выделенные» отправляет выделенное, а не отмеченное;
- режим (`поставить`/`добавить`) и число — в строке ввода, рядом пресеты;
- лог операций — в центре, вывод `gd_currency` построчно.

## Как это работает

### Сейв

```
файл = XOR 0x0B ( base64url( gzip( plist ) ) )
plist = <?xml?><plist gjver="2.0"><dict>...
статы = GS_value/<цифра>, значения строками
```

Запись идёт в оба файла — `CCGameManager.dat` и `CCGameManager2.dat`, — плюс в
AutoCloud-копию Steam (`userdata/<id>/322170/ac/WinAppDataLocal/GeometryDash/`),
потому что Steam синхронизирует локальный сейв сам и без галочки в настройках,
затирая правки старой версией.

### Память

Таблица `GameStatsManager`:

```
узел 0x20 байт:  +0x00 ptr, +0x08 next, +0x10 u32 id стата, +0x14 u32 значение
StatInfo:        stats_instance + 0x248 (current) / +0x288 (delta)
                 +0x08 list_end, +0x18 таблица, +0x30 hash_mask
```

Число на экране считается как `current − delta`, поэтому при записи в память
нужно писать `current = цель + delta`, иначе после любого действия игра
пересчитает и покажет не то, что ожидалось.

Побочный эффект в 2.2: часть статов игнорирует файл и живёт только в памяти
(ID 13, 14, 16-21, 23-29, 31 — алмазы, орбы, осколки, ключи и прочее). Их не
имеет смысла писать в сейв, только `live`/`bulk`. Звёзды, секретные монеты и
user coins через сейв сохраняются нормально.

## Ограничения

- Только Windows.
- Живая правка требует запущенной игры и прав администратора.
- Полный скан памяти — десятки секунд на каждом запуске, отсюда `bulk`.
- Адреса статов меняются от запуска к запуску, всё ищется заново.

## Дисклеймер

Учебный инструмент для разбора формата хранения и работы с памятью процесса.
Правка сейва и памяти может привести к потере прогресса или блокировке аккаунта —
делайте бэкапы, они создаются автоматически, но лишними не будут. Автор не несёт
ответственности за последствия.
